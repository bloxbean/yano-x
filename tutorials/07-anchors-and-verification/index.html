Tutorial 7 — Connect an App Proof to Cardano

To run this outcome with other operators, follow Set up an application.

  • Level: intermediate to advanced
  • Time: about 20 minutes on local devnet
  • Outcome: bootstrap a threshold-enforced script anchor, advance it after app blocks finalize, prove one record against the anchored root, and know which checks need your own Cardano source.

Before you start: finish Tutorial 1 and remove its rehearsal with ./yano.sh appchain try --clean. You need the extracted Yano X JVM distribution, curl, and jq. Every command runs from the distribution’s top-level directory. The exercise’s template selects script anchoring; ./yano.sh appchain anchor then uses the bundled validator and thread policy. To use reviewed replacements, give the anchor:script capability its anchorValidator and anchorThreadPolicy answers in the draft.

An app ledger finality certificate proves that the configured member threshold approved a block. An L1 anchor makes a later application position durable and discoverable through Cardano. These are related but distinct proofs.

2. Lead anchoring and bootstrap the anchor identity

Section titled “2. Lead anchoring and bootstrap the anchor identity”

On a devnet only the lead’s node can anchor. Make alice’s node the anchor leader of orders:

The command creates an anchor wallet key on alice’s node only (secrets/anchor.key), restarts the node with anchoring on, funds the wallet from the self-contained devnet, and, because no member reports an anchor thread yet, calls the chain’s admin/anchor/bootstrap endpoint. Bootstrap consumes a seed UTxO, mints the one-shot thread NFT, and creates the genesis datum. It establishes identity; it does not let the wallet alone claim an arbitrary application tip.

6. Export portable proof material

Section titled “6. Export portable proof material”

Save the material a verifier needs, so it can be checked later without these nodes:

The proof package (appchain-message-proof-v1) holds the message’s inclusion path, the block-message-root and state-record proofs, the evidence bundle, and the anchor reference the node used. Its embedded verification results are explanatory only. The evidence bundle holds the message’s block, every block up to the anchored one, and their finality signatures; verify it with EvidenceVerifier.verify(bundle, trustContext) from yano-core-api, with a trust context you pinned yourself.

Metadata versus script anchoring

Section titled “Metadata versus script anchoring”
PropertyMetadataScript
SetupFund walletFund wallet + bootstrap
L1 enforcementData commitment onlyMonotonic thread + threshold member signatures
Main safety authorityAnchor walletOn-chain validator and member threshold
Typical useLow-cost timestamp/discoveryStrong consortium settlement boundary

Both modes commit application data; only script mode enforces the threshold and monotonic successor rules on chain. Neither checks that a root is correct: in script mode, the members who co-sign do.

Public test networks

Section titled “Public test networks”

For preview or preprod:

  • generate a dedicated raw 32-byte anchor seed;
  • give it to the anchor leader’s node with ./yano.sh appchain anchor --key <seed-file>, which copies it into that node’s secrets/anchor.key without printing it;
  • fund the printed enterprise address with test ADA; the command waits until the funds arrive, and the balance is the spending limit; and
  • choose an anchor cadence (every-blocks) in the draft that matches real L1 timing and fees.

Do not reuse a wallet mnemonic, validator member seed, actor signing key, or API key as the anchor wallet.

8. Clean up

Section titled “8. Clean up”

Local devnet state is disposable. A public script anchor is permanent Cardano history even after local files are deleted.

Go deeper

Section titled “Go deeper”
