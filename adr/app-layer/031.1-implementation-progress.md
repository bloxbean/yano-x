## Review observations

- Kernel access must traverse both the plugin callback facade and the
  startup wrapper; exposing it only on the raw machine loses discovery.
- Catalog-driven component construction needs a narrow host resolver in
  `AppStateMachineContext`; the original context has no provider registry.
- API level increases from 9 to 10 for the additive contracts.
- Legacy composite profiles must keep their original bytes, not merely
  decode successfully under a new codec.
- Raw-body mappings can select any opcode supported by the target codec.
  Evidence restrictions must inspect every target command, not just the named
  descriptor. A regression test covers this bypass.
- Receipt encoding belongs before component commits; receipt capacity must
  never turn an already committed cascade into a rejected receipt.
- Javadoc is part of each milestone: document public contracts, deterministic
  wire/accounting rules, authority boundaries, and infrastructure versus
  business-failure semantics. Do not describe unfinished behavior as guaranteed.
- Governed authorization needs explicit cross-participant read views. The kernel
  now declares read participants, and the engine snapshots their permissions and
  supplies only read-only overlays. Unknown, duplicate and self reads fail
  construction; plugin callback tests cover both facts overloads.
- A real-host registry -> approvals -> document-trail test passes, including
  receipt query/proof retrieval and identical root after persisted restart.
  This is single-node evidence, not completion of multi-node/replay qualification.
- Broad composition contracts/runtime, stdlib, and devtools suites pass after
  the participant-read extension. Focused tests pass again after the latest
  transition input validation and stock-adapter cleanup.
- Host Maven artifacts and matching JVM ZIP were rebuilt successfully after the
  participant-read API change using `0.1.0-pre17-SNAPSHOT`.

## Reviewed architecture extension

The user approved extending the ADR for the governed role-to-map path and
requested autonomous implementation with multiple independent reviewers. In
`ActorApprovalProcessor.apply`, `GovernedCryptoWork.reserve` writes shared
cryptographic-work accounting into actor state even when the command later
rejects. The current kernel can read declared foreign participants, but its
plan writes only its own component. Read access alone does not solve this.

Approved direction: explicitly bounded participant-owned, non-refundable work
accounting (not general foreign business plans), with unchanged standalone semantics and tests
for rejected cascades, quota exhaustion, replay and rollback. Independent
authority-boundary and integration reviews reconciled this design. Governed
role-to-map bindings pass the three-node qualification below. The upstream
change is [Yano PR #147](https://github.com/bloxbean/yano/pull/147).

## Payload, admission and work-accounting review follow-up (2026-09-23)

The original qualification above predates these changes. Independent reviewers
reconciled the size and work design before implementation and reviewed the final
execution and host-admission paths again.

- Baseline payloads are materialized only for baseline subscribers. Unbound and
  native-only sources no longer inherit a baseline-wrapper command-size cap.
  The existing IR field is retained, with a 65,536-byte event default; explicit
  old limits and frozen wire vectors retain their original bytes. Native event
  metadata still consumes capacity, so a near-limit body is not guaranteed to
  produce a valid native event.
- Fixed source work consumes the cascade allowance, not the shared binding
  allowance. Binding evaluation and all derived work remain block-charged;
  rejection retains attempted work, but cannot poison unrelated unbound sources.
- Stateless malformed/size/work/kernel failures reject before local pooling or
  relay. Sequenced submission uses a coherent finalized height/root snapshot
  and the next-height profile. REST returns HTTP 400 with a bounded symbolic
  code, not an accepted message ID. Dynamic execution failures still produce a
  terminal rejected receipt with no business-state/effect commit.
- Host API level 11 adds a documented stateless admission hook; both it and the
  contextual hook run on derived commands. Plugin facades preserve class-loader
  and lifetime boundaries. Declarative profile/workflow version 1.1.0 pins the
  changed consensus work semantics. This is not an in-place retained-chain
  upgrade or a public release.
- Focused regressions cover exact baseline CBOR sizing, maximum plain bodies,
